\section{Introduction}
This project presents the use of Reinforcement Learning to solve the Sokoban game, a complex puzzle involving the movement of boxes to target locations. We use Deep Q Learning (DQN) for this purpose. This report discusses game design within the context of DQN, analyzes the impact of various hyperparameters on the achieved solutions, and presents successful experiments results.

\section{Solution}
\subsection{General approach}
The Sokoban puzzle presents a grid-based world comprising the agent, walls, boxes, and target locations. The objective is to relocate all boxes to their designated target spots while minimizing the number of actions the agent performs. The challenge lies in making optimal choices while avoiding dead-ends and loops of futile actions.

DQN represents a model-free reinforcement learning algorithm that operates on reward: this algorithm uses a neural network to approximate the Q-function, which estimates the anticipated cumulative future rewards associated with each possible action within a specific state (Q-values). By instructing the network to approximate these rewards, DQN can establish a policy that maximizes the expected rewards.

\subsection{Network Architecture}

We employ a deep neural network as the function approximating the Q-values. The network  architecture is illustrated in \figref{fig1} and consists of the following components:

\begin{itemize}

\item Input Layer: The input layer represents the current state of the Sokoban puzzle, which is encoded as an RGB picture of the game state.
\item Convolution Layers: Employed for feature extraction.
\item Hidden Layer: A single hidden layer with rectified linear unit (ReLU) activation function.
\item Output Layer: The output layer corresponds to the Q-values for each possible action. It uses a linear activation function.
\end{itemize}

\subsection{The Agent Reward}
We found that the most crucial aspect for the algorithm's success lies in precisely defining the agent's rewards.
By default, the agent loses 0.1 points for each step it takes, intended to prevent it from taking too long to solve the game. The agent earns 10 points for finishing the game, with an additional 1 point for each box placed on the target (it is penalized with -1 point if it removes the box again).

The main issue was that the agent often failed to finish the game, thereby missing the opportunity to "discover" the 10-points reward at the end. To address this, we modified the rewards: we subtract the Manhattan distance of the boxes from the predefined default reward at each step. This means the agent loses more points if the boxes are far from their targets. This adjustment encouraged the agent to strive harder to move the boxes closer to the targets, thereby increasing its chances of earning the 10 points for completing the game.

This choice proved to be critical: only in this manner was it possible to guide the agent toward progressing in completing the game and to create and adapt its policy accordingly.

\subsubsection{Experience Replay Buffer Size}
Experience replay is the practice of storing an agent's interactions, which include the state, action, reward, and next state, in a dedicated buffer. During the training process, mini-batches of experiences are randomly chosen from this buffer. This reduces the correlation between consecutive experiences during training.
